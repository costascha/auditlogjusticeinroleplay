# auditlogjusticeinroleplay

Ενημέρωση του συστήματος: η εφαρμογή σχεδιάστηκε για ασφαλή διαχείριση αιτημάτων, σύνδεση χρηστών και επαλήθευση πρόσβασης μέσω Supabase, με σαφή διαχωρισμό καθημερινών χρηστών και διαχειριστών.

## Σκοπός

Η εφαρμογή παρέχει ένα απλό σύστημα υποβολής και παρακολούθησης αιτημάτων, με τη δυνατότητα:

- εγγραφής και σύνδεσης χρηστών
- επαναφοράς κωδικού πρόσβασης
- ενδιάμεσης οθόνης φόρτωσης κατά την προετοιμασία της σύνδεσης
- ξεχωριστού, responsive dashboard για κάθε συνδεδεμένο χρήστη
- δημιουργίας ticket με μοναδικό αριθμό
- προβολής μόνο των δικών τους αιτημάτων από τους χρήστες
- προβολής όλων των αιτημάτων και αλλαγής κατάστασης από τους διαχειριστές
- εφαρμογής ασφαλών κανόνων πρόσβασης μέσω Row Level Security (RLS)

## Δημιουργία και χρήση

Η δημιουργία και η χρήση της εφαρμογής ρυθμίζεται από τον Κωνσταντίνο Χαμόρουσιο. Δεν επιτρέπεται η χρήση χωρίς γραπτό αίτημα ή ρητή άδεια, εκτός εάν η χρήση γίνεται για καθαρά ενημερωτικούς, ερευνητικούς ή διοικητικούς σκοπούς και με σεβασμό στους κανόνες λειτουργίας της εφαρμογής.

Το έργο έχει ενημερωτικό και λειτουργικό χαρακτήρα και προορίζεται για ασφαλή και οργανωμένη διαχείριση αιτημάτων, ειδικά σε περιβάλλοντα όπου απαιτείται καταγραφή, παρακολούθηση και διαχείριση αναφορών.

## Άμεση προεπισκόπηση

Δεν απαιτείται εγκατάσταση πακέτων. Στο VS Code επίλεξε **Terminal → Run Task → Preview site**· η εργασία ανοίγει τον τοπικό server στη θύρα `8000`. Στο Codespaces, άνοιξε την καρτέλα **Ports** και επίλεξε τη θύρα `8000`.
Αν δεν υπάρχει `config.js`, η προεπισκόπηση το δημιουργεί από το `config.example.js` (το αρχείο `config.js` παραμένει τοπικό και αγνοείται από το Git).

## Δημοσίευση στο GitHub Pages

Η ροή εργασίας `.github/workflows/deploy-pages.yml` δημοσιεύει αυτόματα το site μετά από push στο `main`. Στο **Settings → Pages → Build and deployment**, το **Source** πρέπει να είναι **GitHub Actions**. Το repository είναι δημόσιο, οπότε ο πηγαίος κώδικας και το ιστορικό του είναι ορατά στο διαδίκτυο. Για διατήρηση ιδιωτικού repository απαιτείται πλάνο που υποστηρίζει ιδιωτικό GitHub Pages ή διαφορετική φιλοξενία.
Για να λειτουργεί η επαναφορά κωδικού, πρόσθεσε το URL της σελίδας στις επιτρεπόμενες διευθύνσεις redirect στο Supabase.
Μετά τη σύνδεση, οι χρήστες μεταφέρονται στο `dashboard.html`. Η σελίδα απαιτεί ενεργή συνεδρία Supabase· οι χρήστες βλέπουν τα δικά τους tickets και οι διαχειριστές βλέπουν όλα τα tickets, τις ειδοποιήσεις εγγραφών και τα εργαλεία αλλαγής κατάστασης.

## Ρύθμιση Supabase και Tickets

Η εφαρμογή χρησιμοποιεί το Supabase για σύνδεση χρηστών, διαχείριση προφίλ και αποθήκευση αιτημάτων.

1. Δημιούργησε ένα project στο Supabase και άνοιξε το SQL Editor.
2. Εκτέλεσε το περιεχόμενο του [`supabase/schema.sql`](./supabase/schema.sql).
   Αν είχες ήδη τον πίνακα `public.profiles`, το script τον μετονομάζει σε
   `public.users` και διατηρεί τα δεδομένα του.
3. Οι νέοι χρήστες εγγράφονται μόνο με username και κωδικό. Η εφαρμογή
   δημιουργεί εσωτερικό email αναγνωριστικό στο Supabase Auth· δεν απαιτείται
   email ή τηλέφωνο από τον χρήστη. Το `public.users` αποθηκεύει username και
   ρόλο. Οι παλιοί λογαριασμοί email συνεχίζουν να συνδέονται με email.
4. Για να κάνεις τον λογαριασμό σου διαχειριστή, αφού πρώτα έχει δημιουργηθεί
   στο **Authentication → Users**, εκτέλεσε στο SQL Editor (αντικατέστησε το
   username):

   ```sql
   update public.users
   set is_admin = true
   where username = 'TO_USERNAME_SOU';
   ```

   Έπειτα αποσυνδέσου και συνδέσου ξανά. Μην ορίσεις `is_admin` μέσω φόρμας εγγραφής
   ή user metadata· μόνο έμπιστος διαχειριστής πρέπει να αλλάζει αυτόν τον ρόλο.

5. Αντέγραψε το `config.example.js` σε `config.js` και συμπλήρωσε το `Project URL`
   και το **anon/public key** από τα API settings του Supabase.
   Μην τοποθετήσεις ποτέ το `service_role` key στον browser.
   Στο **Authentication → URL Configuration**, πρόσθεσε το origin της εφαρμογής
   στα επιτρεπόμενα redirect URLs για λογαριασμούς που χρησιμοποιούν email.
6. Η φόρτωση της βιβλιοθήκης Supabase απαιτεί σύνδεση στο διαδίκτυο.

### Username και κωδικός χωρίς τηλέφωνο

Οι νέοι λογαριασμοί χρησιμοποιούν μόνο username και κωδικό. Για να λειτουργήσει
η εγγραφή, άφησε ενεργό το **Email provider** στο Supabase, απενεργοποίησε το
**Phone provider** και απενεργοποίησε το **Confirm email** (οι λογαριασμοί
username-only δεν έχουν διεύθυνση email για επιβεβαίωση). Η εφαρμογή δημιουργεί
εσωτερικό email αναγνωριστικό με δεσμευμένο domain `.invalid`· δεν αποστέλλονται
email και δεν χρειάζεται να ζητήσεις email ή κινητό από τον χρήστη.

Για να ενεργοποιηθεί η λειτουργία σε υπάρχον project:

1. Εκτέλεσε ξανά το ενημερωμένο `supabase/schema.sql` στο SQL Editor.
2. Εγκατέστησε και σύνδεσε το [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started)
   με το project και κάνε deploy:

   ```sh
   supabase link --project-ref ΤΟ_PROJECT_REF
   supabase functions deploy username-auth
   ```

   Η συνάρτηση απαιτείται για σύνδεση με username και για την αυτόματη μετάβαση
   παλιών λογαριασμών κινητού στο εσωτερικό email αναγνωριστικό. Τα μυστικά
   κλειδιά παραμένουν στο περιβάλλον Supabase.

Οι υφιστάμενοι λογαριασμοί που είχαν username, κινητό και κωδικό διατηρούνται:
στην πρώτη σύνδεση με το παλιό username και τον ίδιο κωδικό, η Edge Function
προσθέτει το εσωτερικό email αναγνωριστικό και συνεχίζει τη σύνδεση. Οι παλιοί
λογαριασμοί email εξακολουθούν να μπορούν να συνδεθούν με email. Η επαναφορά
κωδικού username-only γίνεται από διαχειριστή στο Supabase, επειδή δεν υπάρχει
επαληθευμένο email ή τηλέφωνο.

Για IntelliSense και ελέγχους της Edge Function στο VS Code, εγκατέστησε το
[Deno extension](https://marketplace.visualstudio.com/items?itemName=denoland.vscode-deno)
και το Deno CLI. Το `.vscode/settings.json` ενεργοποιεί το Deno μόνο για τις
συναρτήσεις Supabase.

Χωρίς τα παραπάνω βήματα, η φόρμα μπορεί να εμφανίζεται αλλά η εγγραφή με
username δεν θα ολοκληρώνεται. Τα usernames έχουν 3–32 πεζούς λατινικούς
χαρακτήρες, αριθμούς, τελεία, `_` ή `-`.

Τα tickets λαμβάνουν αυτόματα μοναδικό αριθμό της μορφής `1-1234567890123456`.
Οι χρήστες βλέπουν μόνο τα δικά τους αιτήματα, ενώ οι διαχειριστές βλέπουν όλα τα αιτήματα και μπορούν να αλλάζουν την κατάστασή τους.
Η πρόσβαση ελέγχεται και στη βάση μέσω Row Level Security (RLS).
Κάθε νέα εγγραφή δημιουργεί αυτόματα μία audit καταγραφή στο `public.audit_logs`
και μία εκκρεμή ειδοποίηση στο `public.notification_queue`. Οι διαχειριστές βλέπουν
τις εκκρεμείς ειδοποιήσεις στο dashboard και μπορούν να τις σημάνουν ως κοινοποιημένες.
